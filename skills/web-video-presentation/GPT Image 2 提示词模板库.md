# GPT Image 2 提示词模板库

这个模板库面向 `web-video-presentation` 这类视频化网页演示项目，目标是生成能直接放进章节里的图片素材，而不是泛泛的“好看图”。

## 通用模板

```text
用途：{封面图 / 章节插图 / 信息图 / 历史场景 / 商业案例图}

场景：
{一句话说明画面发生在什么地方}

主体：
{谁 / 什么是画面主角}

关键细节：
1. {必须出现的元素}
2. {必须表达的信息}
3. {补充道具或背景信息}

构图：
{横屏 16:9 / 竖屏 3:4 / 居中 / 左图右文 / 留标题区 / 留空白区}

风格：
{写实 / 插画 / 电影感 / 扁平信息图 / 复古印刷 / 科技感}

约束：
不要水印，不要 logo，不要多余文字，不要边框，不要杂乱背景，不要无关人物。
```

## 1. 科普类

适合：

- 科学原理
- AI / 技术解释
- 生活机制
- 结构拆解

模板：

```text
用途：科普章节插图

场景：
一个清晰、克制的解释型画面，适合网页演示中的一页。

主体：
{概念主体，例如：大脑、细胞、地铁系统、芯片、浏览器、数据流}

关键细节：
1. 用图形化方式表达“输入 - 处理 - 输出”
2. 结构清楚，层次分明
3. 适合后续叠加标题和箭头说明

构图：
16:9 横屏，主体偏左或居中，右侧留给标题或说明文字。

风格：
现代、干净、信息图感、适合讲解视频。

约束：
不要复杂背景，不要艺术化噪点，不要多余装饰。
```

示例：

```text
用途：AI 原理科普插图
场景：一个模型从文本输入到生成结果的流程图
主体：数据流、向量块、输出文本块
关键细节：
1. 左侧是用户输入
2. 中间是模型处理模块
3. 右侧是生成结果
构图：16:9 横屏，留出右上角标题区
风格：科技感、清楚、半写实信息图
约束：不要代码截图，不要额外英文，不要水印
```

## 2. 商业类

适合：

- 公司拆解
- 商业模式
- 品牌增长
- 产品策略
- 行业分析

模板：

```text
用途：商业案例图

场景：
一个用于解释商业逻辑的画面，像网页演示里的分析页。

主体：
{品牌 / 公司 / 产品 / 用户 / 门店 / 供应链 / 收费链路}

关键细节：
1. 明确体现交易或价值流动
2. 体现规模、渠道、成本、利润中的一个重点
3. 适合后续叠加数据标签和结论

构图：
横屏 16:9，信息层次清楚，主视觉和辅助图层分明。

风格：
克制、商业感、现代、适合内容分析。

约束：
不要空泛的概念图，不要花哨装饰，不要过度艺术化。
```

示例：

```text
用途：商业模式拆解图
场景：一个品牌从用户流量到复购的链路
主体：门店、用户、商品、支付、复购箭头
关键细节：
1. 展示流量入口
2. 展示成交路径
3. 展示利润来源
构图：左到右流程图，右侧保留结论区
风格：现代商业信息图、干净、清晰
约束：不要真实品牌 logo，不要杂乱人群
```

## 3. 历史类

适合：

- 历史故事
- 人物命运
- 战争 / 改革 / 转折点
- 地图与时间线

模板：

```text
用途：历史故事插图

场景：
{具体时代、地点、事件瞬间}

主体：
{历史人物 / 场景核心人物 / 地图 / 城市 / 军队 / 船只 / 文书}

关键细节：
1. 必须符合时代背景
2. 必须有明确的情绪或冲突
3. 画面可作为故事节点切换

构图：
16:9 横屏，主体明确，适合配口播和章节标题。

风格：
电影感、写实、低饱和、带时代质感。

约束：
不要现代元素，不要穿帮物件，不要夸张表情，不要卡通风。
```

示例：

```text
用途：晚清历史故事插图
场景：昏暗书房里，一位晚清官员正在查看奏折
主体：一位神情疲惫但克制的官员
关键细节：
1. 木桌、油灯、奏折、旧地图
2. 服饰符合晚清时代
3. 画面有压迫感但不夸张
构图：人物居中偏左，右侧留标题区
风格：电影感、写实、沉稳
约束：不要现代灯具，不要现代纸张质感，不要额外文字
```

## 4. 封面 / 标题图

适合：

- 章节封面
- 视频封面
- 选题标题图
- 系列首图

模板：

```text
用途：视频封面图

场景：
一个能概括整期主题的强视觉场景。

主体：
{一个核心物件或人物}

关键细节：
1. 画面要有明确冲突或问题感
2. 留出大标题位置
3. 让人一眼知道主题是什么

构图：
16:9 横屏，大留白，高识别度，适合后期加字。

风格：
强对比、简洁、醒目、适合点击。

约束：
不要把信息塞满，不要复杂背景，不要过度装饰。
```

## 5. 编辑型提示

适合已有图片时做修图、改图、局部替换。

### 局部修改

```text
保留原图的主体、构图、光线和整体风格，只把 {某一部分} 改成 {新内容}。
其他部分不要改。
```

### 风格迁移

```text
保留原图内容结构，把整体视觉风格调整为 {风格描述}，但不要改变主体信息和构图逻辑。
```

### 文字微调

```text
保留原图画面，只替换标题文字为 {新文案}，保持字体气质、位置和排版层级一致。
```

## 6. 提升命中率的写法

- 先写用途，再写画面
- 先写主体，再写细节
- 先写构图，再写风格
- 约束要明确
- 一个提示尽量只解决一类问题
- 需要字时，把字当成画面元素单独写
- 历史类一定要写时代背景，避免穿帮
- 商业类一定要写流动关系，避免空图
- 科普类一定要写结构层次，避免只剩装饰

## 7. 适合这个项目的提示思路

这个项目不是靠单张图取胜，而是靠“每一章都能接得住口播节奏”。

所以图片最好满足这几个条件：

- 一眼知道主题
- 能留出标题区
- 适合后续叠字
- 适合切章节
- 能和口播内容一一对应

如果一张图只是在“漂亮”，但不能服务讲解，就不适合放进这个项目。
