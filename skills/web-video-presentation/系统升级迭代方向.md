# Web Video Presentation 系统升级迭代方向

## 当前定位

`web-video-presentation` 不是传统 PPT 工具，而是一个面向自媒体、知识视频、产品演示和解释型内容的网页视频生产系统。

当前系统已经具备：

- 自动从文章 / 口播稿生成 `script.md`
- 自动生成 `outline.md`
- 通过 checkpoint 让人审核稿子、outline、主题、素材和开发模式
- 用 Vite + React + TypeScript 构建 16:9 网页演示
- 用 `narrations.ts` 统一管理 step 数和口播文本
- 支持 MiniMax CLI 合成分段音频
- 支持 `manual / audio / auto` 三种播放录制模式
- 支持主题 token 切换视觉风格

所以后续优化重点不是“从手工变自动”，而是让整个系统从“能做”升级到“更稳、更快、更智能、更适合批量生产”。

## 升级目标

### 1. 降低生产成本

减少每期内容从选题到成片所需的人力时间。

### 2. 提高成片质量

让脚本、节奏、视觉、配音、素材之间更加匹配。

### 3. 支持矩阵号批量生产

适配 AI 工具、商业案例、历史故事、生活科学等不同账号方向。

### 4. 提高稳定性

减少章节 step 漂移、音频缺失、素材混乱、录屏节奏不稳等问题。

## 迭代方向一：内容生成质量升级

当前系统已经能生成 `script.md` 和 `outline.md`，下一步应该提升生成质量。

### 可优化点

- 根据平台自动调整口播风格
- 根据账号方向自动选择叙事结构
- 自动识别文章中的关键数字、人物、时间、案例
- 自动给每章添加“信息池”
- 自动判断哪些内容适合做动画，哪些适合做图片
- 自动生成每章的视觉建议

### 示例

同一个选题可以生成不同版本：

- B 站版：完整、解释充分、节奏稍慢
- 抖音版：短、强钩子、强结论
- 视频号版：偏商业和经验总结
- 小红书版：清单化、图解化、可收藏

## 迭代方向二：审核系统升级

现在 checkpoint 依赖人工审核。后续可以增加自动审核层，先让系统自己检查一轮，再交给人确认。

### 可增加的审核项

- 口播是否太书面
- 每章 step 是否过多
- 某一步文字是否太长
- 章节之间节奏是否失衡
- 是否缺少强开头
- 是否缺少结论
- 是否有适合画面化的细节没有提取出来
- 是否存在“口播说了，但画面没有承接”的问题

### 价值

人工审核从“从头看一遍”变成“确认系统指出的问题”，效率更高。

## 迭代方向三：素材与生图系统升级

如果要做商业、历史、科普矩阵号，素材系统会变得非常关键。

### 可优化点

- 每章自动生成图片 prompt
- 区分封面图、章节插图、信息图、背景图
- 支持 GPT Image 2 生图
- 支持参考图风格迁移
- 自动生成素材清单
- 自动命名素材文件
- 自动记录素材来源和用途
- 支持同一人物 / 同一品牌视觉一致性

### 推荐素材结构

```text
assets/
├── cover/
├── chapters/
│   ├── 01-hook/
│   ├── 02-mechanism/
│   └── 03-case/
├── references/
└── prompts/
```

### 推荐新增文件

```text
asset-plan.md
image-prompts.md
```

其中：

- `asset-plan.md` 管理每章需要什么图
- `image-prompts.md` 保存可复用的 GPT Image 2 提示词

## 迭代方向四：章节模板系统升级

当前章节实现仍然依赖开发者按 outline 写 React 组件。后续可以沉淀常用章节模板，提升批量生产效率。

### 推荐模板

- 强钩子开场模板
- 三点递进解释模板
- 时间线模板
- 对比模板
- 商业模式流程模板
- 历史事件复盘模板
- 数据增长模板
- 误区澄清模板
- 总结金句模板

### 价值

矩阵号大量内容结构其实是重复的。模板化之后，Agent 只需要填内容、换视觉、调节奏。

## 迭代方向五：音频与节奏系统升级

当前系统已经支持 MiniMax CLI 分段合成和自动播放。下一步可以让音频更深地参与节奏控制。

### 可优化点

- 自动统计每段音频时长
- 检查某一步是否过长或过短
- 根据音频时长调整动画节奏
- 预加载下一段音频
- 标记异常音频段
- 支持不同账号使用不同声音
- 支持章节级语速建议

### 推荐新增文件

```text
audio-report.json
```

记录：

- chapter
- step
- text length
- audio duration
- warning

## 迭代方向六：录制与发布系统升级

当前系统主要靠浏览器打开 `?auto=1` 后录屏。后续可以把录制和平台输出做得更自动。

### 可优化点

- 自动启动 dev server
- 自动打开录制 URL
- 自动检查音频是否齐全
- 自动检查画面是否加载成功
- 支持横屏长视频
- 支持竖屏裁剪版本
- 支持封面图导出
- 支持章节截图导出
- 生成平台发布文案

### 推荐平台输出

```text
dist-video/
├── bilibili/
├── douyin/
├── xiaohongshu/
└── shipinhao/
```

## 迭代方向七：项目配置化

如果要长期做矩阵号，需要把项目从“每次靠人工约定”升级成“配置驱动”。

### 推荐新增配置

```text
project.config.json
```

示例：

```json
{
  "title": "为什么一个 AI 工具会突然爆火",
  "accountType": "business-analysis",
  "platforms": ["bilibili", "douyin", "xiaohongshu", "shipinhao"],
  "theme": "newsroom",
  "voice": "minimax-2.8-hd",
  "aspectRatios": ["16:9", "9:16"],
  "assetStyle": "clean editorial infographic"
}
```

### 价值

后续 Agent 可以根据配置自动决定：

- 口播风格
- 视觉主题
- 图片风格
- 章节模板
- 平台裁剪方式
- 发布文案方向

## 迭代方向八：质量评分系统

为了批量生产，需要有一套质量评分标准。

### 可评分维度

- 选题钩子
- 口播流畅度
- 章节节奏
- 信息密度
- 画面承接度
- 动效合理性
- 配音匹配度
- 平台适配度
- 封面点击感

### 输出形式

```text
quality-report.md
```

示例：

```text
总分：82 / 100

问题：
- 第 2 章 step 4 口播过长，建议拆成两步
- 第 3 章缺少具体案例，画面支撑不足
- 结尾行动建议偏弱
```

## 优先级建议

### 第一阶段：低成本高收益

1. 增加 `asset-plan.md`
2. 增加 `image-prompts.md`
3. 增加脚本 / outline 自动审核清单
4. 增加常用章节模板
5. 增加音频时长报告

### 第二阶段：生产效率提升

1. 支持一键生成项目配置
2. 支持按账号方向生成不同版本
3. 支持自动生成图片 prompt
4. 支持素材目录规范化
5. 支持章节模板选择

### 第三阶段：系统产品化

1. 平台版本自动生成
2. 自动录制与截图
3. 质量评分系统
4. 多账号内容工作流
5. 选题库和复盘系统

## 最推荐优先做的 5 件事

1. `asset-plan.md`：把每章要什么图说清楚
2. `image-prompts.md`：把 GPT Image 2 生图提示词纳入流程
3. `quality-report.md`：每次生成后自动自检
4. 章节模板库：让商业、历史、科普内容更快落地
5. `audio-report.json`：让配音和节奏可以被检查

## 结论

这个项目现在已经完成了“网页演示 + 口播 + 音频 + 录屏”的基础链路。

下一步真正有价值的升级方向是：

- 内容生成更精准
- 审核更智能
- 素材更系统
- 章节更模板化
- 音频节奏更可控
- 输出更适合矩阵号分发

最终目标不是做一个更像 PPT 的工具，而是做一个解释型视频内容的生产系统。
